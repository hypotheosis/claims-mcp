# Claims viewer

- New static page on the docs site, `docs/site/src/viewer/` (served at `<site>/viewer/`), for
  reading a `claims.json` in the browser:
  - an overview: share supported, counts per verdict, needs attention, progress per `area:` tag;
  - a searchable, filterable claims list;
  - a claim page with the hierarchy, verdict history (with the `Fix:` step highlighted) and
    evidence, where file anchors link to GitHub at their pinned commit.

  Views have shareable addresses.
- Loads from a public GitHub repository through `raw.githubusercontent.com` (no API calls, no
  tokens), or from a local file. `?repo=owner/name[&ref=][&path=]` opens a ledger directly.
  Private repositories aren't supported, because every project site under a `github.io` account
  shares one browser origin.
- Display only: it doesn't check seals or recompute gaps.
- Vanilla JavaScript ES modules and Pico CSS 2.1.1 (SRI-pinned), with the viewer's own stylesheet,
  fonts and light/dark themes; no build step. mdBook copies the files through unchanged, so the
  existing docs workflow publishes it.
  - `model.js` (parsing, counts, filters, routes, anchor links) and `source.js` (loading) do no
    DOM work.
  - `app.js` builds every element with DOM APIs, never `innerHTML`, because catalog text is
    untrusted.
- Tests: `docs/site/viewer-tests/` (21 tests, Node's built-in runner, no packages), including a
  check that the viewer counts this repository's active claims the same as
  `claims-mcp tldr --json`. They run in CI's `check` job (Node 24 via a pinned
  `actions/setup-node`) and locally with `just viewer-test`. `docs/site/package.json` only marks
  the viewer's `.js` files as ES modules for Node; it isn't published.
- Docs: a "Claims viewer" page under a new Tools part of the sidebar, and a README link.
- Design and plan: `docs/superpowers/specs/2026-10-31-claims-viewer-design.md`,
  `docs/superpowers/plans/2026-10-31-claims-viewer.md`.
