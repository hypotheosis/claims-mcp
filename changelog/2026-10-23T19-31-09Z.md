# Next-steps TL;DR

- New `next_steps` MCP tool and `claims-mcp tldr [--limit N] [--json]` subcommand: open
  active leaf claims ranked into tiers (0 integrity failure, 1 refuted, 2 open at integrity 3-4,
  3 the rest counted per area), each with one next step taken from the last `Fix:` in its
  latest verdict rationale, falling back to the first sentence before the marker.
- Roll-up parents (claims with active children) are counted, not listed.
- `tldr` renders into a buffer and treats a closed pipe as success, so
  `claims-mcp tldr | head` exits 0 without logging an error.
- `claims-audit` skill: `refuted` and `not_enough_info` rationales must end with
  `Fix: <one concrete next step>`.
- Refactor: `is_stale` and `is_high_integrity` extracted from `classify_gaps` and shared with
  the new module (`src/report/next_steps.rs`).
- On `bdc.json` (bolt_deployment_controller, 1049 active claims): 32 wrong, 266 unproven at
  integrity 3-4, 109 other. The default output is 57 lines.
- Spec: `docs/superpowers/specs/2026-10-23-next-steps-tldr-design.md`. Plan:
  `docs/superpowers/plans/2026-10-23-next-steps-tldr.md`.
- Final-review follow-ups: the claims-audit skill and server instructions point to `next_steps`
  and forbid cross-referencing `Fix:` text; the STOP banner shows the first integrity problem
  instead of always saying restore from git; singular/plural wording in the summary and banner;
  line breaks in statements and steps are flattened in the Markdown output.
- PR #15 review: parents whose active children are all done but which have no fresh
  `supported` verdict are now listed as ready roll-ups (`rollup_ready: true`, counted in
  `summary.rollups_ready`) with a "record the roll-up verdict" step, so a catalog whose leaves
  are all done no longer reports zero open work.
