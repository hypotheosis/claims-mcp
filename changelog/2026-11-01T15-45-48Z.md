# Per-call ledger choice (issue #31)

- Every MCP tool takes an optional `catalog` argument: the ledger file for that call only,
  absolute or relative to the server's working directory. The call reads or writes that file,
  and anchors pin `HEAD` of the git repository that holds it. Calls without it use the
  server's `--catalog`, exactly as before.
- Implemented as one generic wrapper, `OnLedger<T>` in `src/server.rs`, that flattens each
  tool's own parameters beside `catalog`; `recheck` now takes `OnLedger<NoParams>`. Two
  helpers, `ClaimsServer::read` and `ClaimsServer::mutate`, resolve the ledger once per call
  and pass its store to the operation, which replaces the store cloning each handler did.
- An empty `catalog` path is refused with a validation error.
- Chose a per-call argument over an `open_catalog` tool. Switching the server's ledger would
  be session state shared by every agent on the connection, and concurrent subagents would
  race on it.
- The server instructions, the tools, CLI, install and security reference pages, and the
  claims-audit skill's pull-request mode now describe the argument. The skill keeps
  `scripts/claims_call.py` as the fallback for servers at 0.2.4 or earlier, which ignore
  unknown arguments silently.
- Not done: the `claims-mcp call <tool> <json>` one-shot CLI that the issue suggests as an
  optional extra.
- Tests: two ledgers in two repositories written through one server whose own ledger is
  outside git, anchors following the named ledger's repository, the empty-path refusal,
  flattened deserialization, and every tool's schema offering an optional `catalog`.
