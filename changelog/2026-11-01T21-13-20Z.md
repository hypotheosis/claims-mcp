# Drop claims_call.py; check for catalog support by asking the server

- Removed `skills/claims-audit/scripts/claims_call.py`. Since 0.2.5 every tool takes a
  `catalog` argument, so an agent in another checkout names its ledger with the tools it already
  has. The script only remained as a fallback for servers before 0.2.5.
- The skill's pull-request mode no longer tells agents to read the tool schemas to see whether
  the server supports `catalog`. A client can keep showing the schema it loaded before the
  server was upgraded or reconnected, which made the check report an old server when a new one
  was connected. Agents now call `list_claims` with `catalog` naming a ledger in a directory
  that does not exist: a server with the argument fails to open it, and a server that answers
  normally ignored it. An empty `catalog` would also be refused, but some clients drop an empty
  argument value before sending the call, so the probe uses a path. In that case the agent
  stops and asks for an upgrade and a restart or reconnect, instead of falling back to the
  script.
- The tools reference's "Choosing the ledger" section describes the same check.
