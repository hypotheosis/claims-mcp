# claims-mcp 0.1.0: PDF audit reports with Typst (issue #2)

## Added
- `report/claims-report.typ`: a Typst template that reads a catalog with `json()` and renders a
  self-contained PDF audit report: cover (artifact, version, date, catalog commit, auditors,
  method), result totals with evidence by stance and an assessment, findings for every
  `refuted` and `not_enough_info` claim, points for the evaluator, coverage by integrity level
  with the rigor check, all eight gap categories, the claim hierarchy, a landscape traceability
  matrix (repeating header, rows never split, wrapping locators), an evidence appendix with the
  full verdict history, and reproduce commands.
- The template recomputes totals, gaps, and the matrix with the spec section 4.1 rules and
  exposes them as `<audit-report>` metadata. Timestamps are compared at nanosecond precision and
  normalized to UTC, so `stale` matches `audit_report` exactly.
- `report/audit-notes.toml`: free-text sidecar (assessment, evaluator points, repository) for
  the first self-audit.
- Tests `typst_template_matches_repo_catalog`, `typst_template_handles_empty_catalog`, and
  `typst_template_matches_every_gap_and_retired_claims` compile the template (no warnings
  allowed) and compare `typst query` output with `audit_report`. They are skipped when `typst`
  is not on `PATH`.
- `justfile` with `fmt`, `clippy`, `test`, and `report` recipes.

## Changed
- Verdict markers carry a text label (`SUPPORTED`, `REFUTED`, ...) as well as a fill color, so
  the PDF survives grayscale printing.
- Claims link to issues through an `issue:N` tag; `CLM-0034` is tagged `issue:1`.
- README gains a "Generate a PDF report" section; the `claims-audit` skill's Report step
  mentions the PDF as an optional output.
- `.gitignore` ignores the generated `/audit.pdf`.

## Design notes
- PDF generation stays outside the server: an MCP tool that shells out to `typst` would break
  the pure-ledger rule (spec section 2, CLM-0020). Embedding the `typst` crate as a
  `claims-mcp report` subcommand was left for a later discussion because of its dependency tree.
