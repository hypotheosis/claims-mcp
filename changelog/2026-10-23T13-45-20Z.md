# claims-mcp 0.1.0: CI, release pipeline, and install docs (issue #4)

## Added
- `.github/workflows/ci.yml` runs on pull requests and on pushes to `main`. It runs
  `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, a warning-free build, and
  `cargo test` with Typst 0.14.2 installed and `REQUIRE_TYPST=1`. It also runs `cargo test` on
  Windows and macOS and `cargo check` on the MSRV (1.89), then renders `just report` from the
  PR head commit and uploads `audit.pdf` as the `audit-report-pr-<number>-<commit>` artifact.
- `.github/workflows/release.yml` runs when a `v*` tag is pushed. It fails if the tag is not
  `v` plus the `Cargo.toml` version or the tagged commit is not on `main`. It then reruns
  `ci.yml` on the tagged commit and builds static musl Linux (x86_64, aarch64), Windows x86_64
  (MSVC), and macOS (x86_64, aarch64) binaries. It then publishes a GitHub release with one archive per target (binary, README,
  `skills/`), a `.sha256` file for each archive, and the audit report. A PR that edits
  `release.yml` runs the builds as a dry run with no publish step.
- Third-party actions are pinned by commit SHA. Workflows default to `contents: read`, and
  only the publish job gets `contents: write`.

## Changed
- The README "Build", "Register with Claude Code", and "Install the skill" sections are now
  one "Install" section. It covers release downloads with checksum verification,
  `cargo install --git`, building from source, `claude mcp add` at each scope (with the
  matching `.mcp.json` entry), and installing the skill for the user or for a project.
  "Development" now documents the CI checks and how to cut a release.

## Notes
- Release archives contain no license file, because the repository does not have one yet.
- The macOS binaries are not signed or notarized. The README shows how to clear the quarantine
  flag.
