# Report files ship with the binary (issue #18)

A project that installed claims-mcp from a release could not render the PDF report or write its
notes file: the template and the notes example existed only in this repository's `report/`.

- `src/report/files.rs` compiles `report/claims-report.typ`, `report/text.typ`, and
  `report/audit-notes.example.toml` into the binary with `include_str!`, so every install
  carries the report files that match its version. `report/text-tests.typ` stays repo-only.
- New CLI command `claims-mcp report init [DIR]` (default `report`). It writes the three files,
  replacing older copies so they match the binary, and creates `DIR/audit-notes.toml` only when
  it does not exist (`create_new`, so it is never overwritten). The new notes file is the
  example with every setting commented out, so an unedited file cannot put the example's
  invented project (`example-service`, CLM-0042, issue #12) into a report. It prints `wrote` or
  `kept` for each path.
- The MCP server now has the resources capability and lists the three files as read-only
  resources, `claims://report/<file name>`, served byte-identical to `report/`. Unknown URIs
  return `resource_not_found`. `get_info` is written by hand because `#[tool_handler]` only
  generates it with the tools capability; the server instructions now name the notes example
  resource and `report init`.
- The `claims-audit` skill's Report step runs `report init` (or reads the resource when there is
  no shell) and renders `report/claims-report.typ`, no longer a path in the claims-mcp
  repository. The README's "Generate a PDF report" section, the template's reproduce section,
  and the example's header comment say the same.
- Tests: embedded files equal `report/` byte for byte; `report init` writes every file and keeps
  an existing notes file; a real rmcp client over an in-memory pipe lists the resources and reads
  the notes example; and (with Typst) both detail levels render warning-free from `report init`
  output in an empty directory with the documented relative-path command. `rmcp`'s `client`
  feature is a new dev-dependency for that test.
- Checked by hand: the release binary in an empty directory with a copy of `claims.json` ran
  `report init`, `verify --json`, and both `typst compile` commands; a second `report init` kept
  the edited notes file.
