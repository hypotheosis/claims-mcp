# Pull request mode for the claims-audit skill

- Added "Auditing a pull request" to `skills/claims-audit/SKILL.md`: an audit an issue-to-PR
  workflow runs on its own change before opening the PR. A fresh subagent on a different model
  audits the issue's requirements and the PR description's statements, rechecks anchors the diff
  touched, and classifies refuted claims as ours (must be fixed first) or elsewhere (recorded
  and flagged). Repositories without a tracked ledger get a table in the PR description with no
  claim ids and no ledger writes.
- Added `skills/claims-audit/scripts/claims_call.py`, a standard-library client that starts
  claims-mcp on stdio for a ledger named per call, for agents working in a checkout other than
  the one their MCP client started in (git worktrees).
- Documented that two branches that both add evidence can merge without a git conflict into a
  ledger with duplicate ids, which the server then refuses to read, in the skill and in the CI
  guide.
